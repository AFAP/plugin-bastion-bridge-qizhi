# 通用堡垒机 SSH 桥接器使用说明

> 本文档面向**使用者**（运维人员或 AI 助手），说明如何通过「堡垒机 SSH 桥接器」操作目标 Linux/Unix 服务器。不涉及桥接器内部实现。

---

## 0. 端口约定（先读这里）

每个桥接器在本机监听一个 HTTP/WebSocket 端口，**仅绑定 `127.0.0.1`**。

- 本文档示例统一使用 `http://127.0.0.1:8766`（下文记作 `<BASE>`）。
- **实际端口以桥接器启动时告知的为准**（不同厂商的桥接器使用不同端口，由部署者直接告诉你）。拿到实际端口后，替换下文所有示例中的端口即可。

---

## 1. 这是什么

「堡垒机 SSH 桥接器」是一个安装在运维本机的 Windows EXE，注册为堡垒机控制台中「本地工具」的启动路径。用户在堡垒机点击 SSH 资源时，桥接器被唤起并自动建立到目标服务器的 SSH 连接，随后在本机启动 API 服务。此后，人或 AI 即可通过这组本地接口在目标服务器上执行命令、流式查看输出、发送交互输入。

**所有厂商的桥接器对外 API 完全一致**，区别仅在对应的堡垒机、EXE 文件名和端口。

---

## 2. 使用流程

1. **用户侧（一次性）**：在堡垒机「工具配置」中，将本地工具路径设为桥接器 EXE 的完整路径。
2. **用户侧（每次）**：在堡垒机资源列表选择 SSH 资源，工具选「本地工具」，点击「连接服务」。桥接器被唤起，数秒后完成连接。
3. **AI 侧**：调用健康检查确认连接，然后开始执行命令：

```bash
curl <BASE>/health
```

响应：

```json
{ "status": "ok", "connected": true }
```

- `connected: true` → 可以执行命令
- `connected: false` → SSH 连接失败，先排错（见第 6 节），不要执行命令

---

## 3. API 说明

### 3.1 健康检查

```http
GET <BASE>/health
```

### 3.2 执行单次命令（最常用）

```http
POST <BASE>/execute
Content-Type: application/json

{ "command": "uname -a", "timeout": 30 }
```

响应：

```json
{ "stdout": "Linux server 5.15.0 ...\n", "stderr": "", "exit_code": 0 }
```

- `timeout` 可选，默认 30 秒。
- `exit_code`：`0` 成功；非 0 失败（结合 `stderr` 分析）；`-1` 表示 SSH 未连接或执行异常。

### 3.3 实时流式输出（SSE）

适用于耗时长、需实时查看的命令（`ping`、`tail -f` 等）：

```http
GET <BASE>/stream?command=ping%20-c%204%20127.0.0.1
```

事件流：`start` → 若干 `stdout`/`stderr` → `exit`（附退出码）→ `end`；出错时为 `error`。

### 3.4 交互式输入

当运行中的命令需要输入（确认 `y/n`、sudo 密码等）：

```http
POST <BASE>/input
Content-Type: application/json

{ "data": "y\n" }
```

### 3.5 WebSocket

地址：`ws://127.0.0.1:<端口>/ws`，适合持续会话。发送 `{"command": "...", "timeout": 30}` 收 `result` 事件；发送 `{"data": "..."}` 进行交互输入，收 `input_status` 事件。

---

## 4. 使用建议

### 4.1 接口选择

| 场景 | 推荐接口 |
|---|---|
| 简单查询（`uname -a`、`df -h`） | `POST /execute` |
| 耗时长或需实时输出 | `GET /stream` 或 WebSocket |
| 需要交互输入 | `POST /input` |
| 持续会话、多命令状态保持 | WebSocket `/ws` |

### 4.2 结果处理

每次执行后检查 `exit_code`：`0` 为成功（无输出也属正常）；非 0 结合 `stderr` 向用户解释失败原因；`-1` 转入排错。

### 4.3 连接保活

桥接器内置空闲保活（默认 60 秒无命令时自动执行无害命令防止断连），使用者无需关心。

### 4.4 典型示例

```bash
# 检查连接
curl http://127.0.0.1:8766/health

# 执行命令
curl -X POST http://127.0.0.1:8766/execute \
  -H "Content-Type: application/json" \
  -d '{"command": "df -h"}'
```

Python：

```python
import json, urllib.request

BASE_URL = "http://127.0.0.1:8766"  # 替换为实际端口

def execute(command, timeout=30):
    req = urllib.request.Request(
        f"{BASE_URL}/execute",
        data=json.dumps({"command": command, "timeout": timeout}).encode(),
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req, timeout=timeout + 5) as resp:
        return json.loads(resp.read().decode())

health = json.loads(urllib.request.urlopen(f"{BASE_URL}/health", timeout=5).read())
assert health.get("connected"), "桥接器未连接"

print(execute("uname -a"))
```

---

## 5. 安全注意

- API 仅监听 `127.0.0.1`，但本机任何程序均可调用，请勿在不受信环境运行。
- 不要将命令结果中的敏感信息（密码、密钥等）外传到本机以外。

---

## 6. 排错

| 现象 | 处理 |
|---|---|
| 无法访问 API | 桥接器未被唤起。检查堡垒机本地工具路径配置，重新点击「连接服务」。 |
| `/health` 返回 `connected: false` | SSH 连接失败，让用户查看桥接器日志中的错误（如认证失败、网络不通）。 |
| `exit_code: -1` | SSH 未连接，先确认 `/health`。 |
| 端口连不通 | 确认使用的是部署者告知的实际端口，而非示例端口。 |

## 7. 快速参考

| 操作 | 方法 |
|---|---|
| 检查状态 | `GET /health` |
| 执行命令 | `POST /execute {"command": "...", "timeout": 30}` |
| 流式输出 | `GET /stream?command=...` |
| 发送输入 | `POST /input {"data": "..."}` |
